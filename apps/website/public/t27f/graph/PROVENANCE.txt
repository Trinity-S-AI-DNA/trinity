/t27f/graph/ -- where every byte on the page comes from
=======================================================

The T27F graph view (epic gHashTag/trinity#1648, RFC gHashTag/trinity#1649). The page draws one
box per node and one line per edge of a .t27 spec. It holds no graph, no layout and no verdict
of its own:

  spec_graph_export.t27   reads the spec's bytes into the graph (exact nodes and edges only;
                          at most 1024 nodes and 4096 edges since t27#10231 -- was 192 and 254;
                          over that it refuses, never truncates)
  spec_graph_view.t27     places, sizes and colours every box and line
  spec_graph.t27          the graph IR both of them share

Both run as t27f.wasm. t27f_graph.js (45 lines, comments included) is the whole of the hand-written
graph JavaScript: it loads the wasm, writes the spec's bytes in, loops over nodes and edges and emits
SVG. It is one module shared by /t27f/graph/ (graph.js, 8 lines: fetch the picked spec) and by the
Spec Explorer's Graph layer (src/components/SpecGraphView.tsx imports it); there is no second copy. The one number it computes is how many characters of "kind name" fit in a box's first line
(font size x 0.6, the width of the JetBrains Mono the boxes are set in); the full text is in the
box's tooltip. The same wasm now also serves /t27f/live/ (the work graph and the HUD of
gHashTag/t27#10260 and #10262, wg_*/hs_* exports); that page loads this directory's file and
adds no second build.

Colours
  Every box fill, outline, dash and line colour comes from spec_graph_view.t27 (VIEW_LABEL_FILL,
  VIEW_LABEL_STROKE, VIEW_LABEL_DASH, VIEW_TEXT, VIEW_BACKDROP), changed in gHashTag/t27#10215
  (closes #10213). They are the t27.ai site's own tokens (apps/website/src/index.css :root and
  src/lib/explorerTheme.ts in gHashTag/trinity), not docs/BRAND-KIT.md: exact is the site
  green 00FF88, derived the golden FFD700, suggested the blue 58A6FF, unknown the muted
  8B9490. The dash per label stays distinct (solid, 6, 3, 2) so a label survives a colour-blind
  reader. The CSS in index.html styles the page chrome only (background, fonts, header,
  picker); it never recolours a box or a line.

Source
  gHashTag/t27 master 23232812d0, specs/t27f/: spec_graph.t27, spec_graph_view.t27 and
  spec_graph_export.t27 as of #10231 (caps 1024/4096), plus specs/tutorial/08_modules_and_arrays.t27
  (specs/*.t27 here are byte-identical to that commit; the 2026-10-18 build was from
  538df0750 and 290ff17df, before the cap raise)
Compiler
  t27c 0.5.2 built from gHashTag/t27 master 23232812d0 (the use-splice fix #11012; t27c 0.5.2
  as released, sha cb1115f6..., leaves the Live modules' generated Zig uncompilable), zig 0.16.0,
  on the owner's Mac -- the first build off the Railway lab; the record below is of that build
Built in
  gHashTag/t27-mcp wasm/ (export.zig is the hand glue: byte buffers, getters and the wg_/hs_
  exports of the Live modules, no spec knowledge). It is built with the reel, deck,
  spec_graph_view, spec_graph_export, spec_graph_outline, work_graph and hud modules.
  wasm/BUILD there has the full recipe.

Checksums
  t27f.build, next to this file, is the record: `#` lines hold the inputs of the build (closure digest,
  zig version, t27c sha256) and every other line is `<sha256>  <file>` for the vendored wasm, the vendored
  view constants and the vendored specs. It is a copy of the lines of gHashTag/t27-mcp wasm/t27f.build
  that name files kept here, produced by the rule in gHashTag/t27 specs/t27f/build.t27 (#10229), not typed by hand. Check it with
  `npm run check:t27f` in apps/website; one changed byte names the file. (The generated Zig the wasm is
  built from is not vendored; its checksums are in the t27-mcp record.)

Reproduced on the Railway lab on 2026-10-18 from these vendored specs:
  t27c gen-js spec_graph_view.t27 gives spec_graph_view.mjs byte for byte;
  t27c gen spec_graph_view.t27 and spec_graph_export.t27 give the two .zig above;
  zig build-exe export.zig -target wasm32-freestanding -fno-entry -rdynamic -O ReleaseSmall
  -femit-bin=t27f.wasm gives t27f.wasm byte for byte.
(Generate from a directory laid out as specs/t27f/, so that the `use t27f::...` lines resolve.)

Not here yet: derived edges. t27 has the derive pass (spec_graph_derive.t27, t27#10198), but it
is a separate module that the wasm glue does not call, and wiring it in means more hand-written
glue. Until the wasm exports it, every edge on the page is exact, and the page says so.
