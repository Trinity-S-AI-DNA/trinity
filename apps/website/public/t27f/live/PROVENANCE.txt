/t27f/live/ -- where every byte on the page comes from
======================================================

The T27F Live page (the HUD milestone of T27F Live, gHashTag/t27#10262, epic #10266; the work
graph is #10260). The page replays a recorded log of agent events through two specs and draws
what the second one says. It holds no graph, no scene and no verdict of its own:

  work_graph.t27   joins each bus record into the one work graph: nodes (SPEC, AGENT, TASK,
                   ACTION, ARTIFACT), edges (READS, ASSIGNED, PERFORMS, PRODUCES, VERIFIES,
                   BLOCKS), every node and edge carrying one of the four provenance labels.
                   apply_event is pure (FR-001); past a cap it refuses and the graph is left as
                   it was (FR-003); no payload exists anywhere in the model (FR-004).
  hud.t27          reads the graph into the HUD scene: one task card per node, carrying that
                   node's kind and provenance label, plus a status bar exactly when the graph
                   has work to report, naming the node count and the frame. hud_scene_of is
                   pure; an empty graph paints an empty HUD. hud_mirror (the a11y mirror) is
                   an entry point for the next spec and is not wired yet.

Both run as t27f.wasm -- the SAME build the /t27f/graph/ page loads (../graph/t27f.wasm, one
file, one record: gHashTag/t27-mcp wasm/t27f.build). live.js (38 lines, comments included) is
the whole of the hand-written page JavaScript: it loads the wasm, fetches the recording, feeds
each event's columns to wg_apply, calls hud_build once, reads the scene back through the hs_
getters and emits one div per card plus the status bar line. It decides no layout, no colour
and no state: a card's text and data-kind / data-label attributes are the spec's own numbers
named through work_graph.mjs's generated constants, and the CSS above maps those names to the
site's tokens. hud.t27 states no colour; the kind hues here are the graph page's (agent the
site green 00FF88, spec the blue 58A6FF, task the golden FFD700, artifact the amber F0A020,
action muted 8B9490) and a dashed border still marks a label weaker than exact.

The recording
  live.json, format t27f-work-graph-log/1: one "columns" object whose arrays are the fields of
  work_graph.t27's Event -- kind, from_pid, to_pid, task_no, deliver, reason, seq, spec_id --
  one entry per event, in feed order. from_pid / to_pid are the feed's pids, already resolved
  through queen::actors pid_of (slot << 32 | gen). The file is generated, not typed: the
  columns are work_graph_fixture.t27's (gHashTag/t27), the recorded feed the spec's own replay
  test runs, read out with `t27c gen-js work_graph_fixture.t27` and pid_of resolved -- 1,024
  events, 948 nodes, 2,945 edges. The fixture's own header says what replaces it: when the
  Queen's runtime publishes its own feed, a log in this format replaces live.json and the page
  replays it unchanged.

Source
  gHashTag/t27 master 23232812d0, specs/t27f/: work_graph.t27 (#11846's hud.t27 on #11752's
  foundation), work_graph_fixture.t27, spec_graph.t27, spec_graph_view.t27 and
  spec_graph_export.t27 as of #10231 (SpecGraph caps 1024 nodes and 4096 edges, u16 indices).
  work_graph.mjs and hud.mjs here are t27c gen-js of the same specs; work_graph.mjs carries
  the NK_/LABEL_/WG_ constants the page names kinds and labels through.
Compiler
  t27c 0.5.2 built from gHashTag/t27 master 23232812d0 (the use-splice fix #11012 is required:
  t27c 0.5.2 as released leaves the generated hud.zig uncompilable -- node_of, a private
  transitive dependency, is ambiguous between queen/actors.t27 and t27f/work_graph.t27 and is
  not spliced), zig 0.16.0. Built on the owner's Mac, the first build off the Railway lab; the
  full record is gHashTag/t27-mcp wasm/t27f.build and wasm/BUILD.
Built in
  gHashTag/t27-mcp wasm/ (export.zig is the hand glue: byte buffers, getters and the wg_/hs_
  exports -- fields only, no spec knowledge). The wasm's Live exports: wg_reset, wg_apply,
  wg_nodes, wg_edges, wg_node_kind, wg_node_label, wg_node_id, wg_edge_kind, wg_edge_label,
  wg_edge_from, wg_edge_to, hud_build, hs_element_count, hs_status_bar, hs_status_node_count,
  hs_status_frame, hs_card_count, hs_card_kind, hs_card_label.

Check the files kept here with
  grep -v '^#' t27f.build | shasum -a 256 -c -

Frame
  The replay here is one paint of the finished graph, and the frame the status bar names is
  the number of events applied. measure_live.t27 is the law for the 60 fps replay measurement
  and is a later milestone; nothing on this page claims a measured frame rate.

Not here yet: the mirror (hud_mirror returns 0 until the next spec builds its lines), the live
wire (live_stream.t27, M4 -- this page replays a recording, it opens no stream), and the log
ticker, metric chart and work-graph inset of hud.t27's kinds, which the scene does not carry
yet: the scene is cards and the status bar, and the page draws exactly that and no more.
